DATABASE / API CONTRACTS
Migration 007 follows 001-006; apply through the trusted Supabase migration process.
New RPC apply_to_be_assistant(): no parameters; derives auth.uid(); community_user
or assistant roles only; creates default pending/not_started/unavailable record or
returns the existing row. Profile role is unchanged, preserving community features.
New RPC review_assistant(p_assistant_id uuid, p_verification text, p_training text,
p_expected_verification text, p_expected_training text, p_reason text default '').
Real database admin role required; validates statuses/reason, locks the row and
rejects stale statuses with 40001. Returns the saved assistant row and appends an
assistant_reviews audit row. Audit SELECT is admin-only; browser writes are denied.
Revoked eligibility clears availability. Existing status values are unchanged.
Availability uses the existing own-row RLS and availability-only UPDATE privilege.
It does not grant access to jobs or automatically cancel/reassign existing work.
Developer Mode never changes database permissions. No new Express routes required.
No new Storage buckets or environment variables. Existing avatars behavior remains.
