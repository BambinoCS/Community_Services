MIGRATION 008 / CONTRACT
item_handoffs: one active arrangement for a donation or item request, with real
participants, full quantity, collection/delivery addresses and transport mode.
Modes: self_collect, self_deliver, assistance.
States: waiting_assistant, arranged, completed, cancelled.
chat_messages: server-derived sender, validated text, unique client retry ID.
RPCs: start_item_handoff, item_handoff_participants, waiting_item_deliveries,
claim_item_delivery, finish_item_handoff, send_chat_message.
RLS: only donor, recipient and assigned still-eligible helper can read a chat.
An unrelated admin or developer cannot read private conversations.
Assistant matching requires available + verified + training completed, excludes
participants, checks active service/delivery work, and locks the chosen assistant.
No free helper means a waiting delivery. The waiting queue exposes item/quantity,
not names or addresses; accepting grants access to its conversation.
Reserved donation owners cannot bypass the arrangement to edit/relist an item.
Creation, reservations and message sends use UUID retries and transactional SQL.
Chat history loads 50 messages at a time. Visible-page polling runs every 10 seconds.
Drafts/nonce fallback survive connection errors, including in-memory fallback when
sessionStorage is unavailable (reload persistence then requires browser storage).

MIGRATION 009 / CONTRACT
RPCs: admin_overview, admin_list_records, admin_moderate_record.
All require the actual database admin role; Developer Mode cannot grant access.
Lists are paged in 50-row batches with server-side filters and literal name search.
User lists omit email, phone, avatar paths and credentials.
Moderation: cancel only open unassigned requests or available unreserved donations.
Report reviews store private notes/reviewer/time separately, without changing the
report's existing status or inventing a resolution. Admin-only audit tables retain
moderation history. No direct browser writes to these new administrative tables.
