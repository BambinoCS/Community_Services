COMMUNITY SERVICES — PERSONAL PROFILE FOLLOW-UP
Date: 2026-09-27
Feature: Profile button, personal information editing and profile pictures

OWNER REQUEST
Add a Profile button next to Sign out that opens a page where the signed-in
user can have a profile picture and edit personal information.
This follow-up explicitly extends the original auth-only scope to personal
profile editing and avatar uploads. Other business workflows remain untouched.

IMPLEMENTATION
- Shared auth guard adds one Profile button beside Sign out across guarded pages.
- New root profile.html works with GitHub Pages project-directory navigation.
- Protected account page is available to any authenticated role, including
  developers previewing another interface. It always edits the actual account.
- Editable first name, last name and optional phone. Sign-in email is read-only.
- Picture selection, local preview, image decoding/type/size validation, replace,
  remove-from-profile, initials fallback, cancel and save feedback.
- JPG, PNG and WebP up to 5 MB; existing public avatars bucket.
- Upload path uses authenticated UUID / random filename. Original filenames and
  user-supplied IDs are not used. No upsert or role mutation.
- Profile save updates only first_name, last_name, phone and optional avatar_path.
  The existing RLS/column grants apply. No migrations or server secrets added.
- Unsaved changes survive normal visibility/auth rechecks. Refresh reloads saved
  details. Controls prevent duplicate saves; failures show honest error messages.
